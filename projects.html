4 周，做一个真有人在用的 Agent

从「我想做一个东西」到「这个东西上线了，每周有 N 个人在用」。

为什么一定要做项目

这门课的判断标准是「你能不能搭出一个能用的 Agent」，不是「你能不能讲清楚 Agent 是什么」。讲清楚只是及格线，做出来才算这门课及格。

4 周的项目不是表演。我们要求你的 Agent 至少被一个真实用户在真实场景里用一周。可以是同班同学、你的导师、你爸妈、你的实习生——重要的是「真人在用」，不是「我自己觉得挺好」。

硬性规则

  • 必须用大模型。可以是任何 LLM（GPT-4 / Claude / Gemini / DeepSeek / Qwen / 智谱 / 自部署均可）。
  • 必须有工具调用。纯聊天不算 Agent——它得动点什么（读文件 / 查库 / 调 API / 写文件 / 发消息）。
  • 必须有 trace。我们能看到 Agent 做了什么、为什么做、什么时候停。
  • 必须有安全边界。危险操作（删文件 / 发邮件 / 写数据库）必须有人类授权或可回滚。
  • 必须有真实用户反馈。你得让至少一个人用一周，记下他用了什么、卡在哪里、为什么卡。

扣分项：用了别人做好的低代码平台直接出图不算（自己再调才算）；只跑通教程 demo 不算；演示视频里全是截图不算——要现场跑。

4 周里程碑

周次截止物说明
第 1 周选题 + 提案（1 页）你想做什么、为什么、真用户在不在、能不能在 3 周内搭起来。
第 2 周Demo Day · 第一版5 分钟讲清楚问题、架构、当前能做什么、还不能做什么。
第 3 周内测版 + 5 个用户至少 5 个真实用户用过，留下反馈；你修过至少 3 个 bug。
第 4 周最终 demo + 复盘公开展示，10 分钟讲 + 5 分钟答辩 + 5 分钟互评。

组队与分工

2–4 人一组。第 1 周周日晚 12 点前提交提案 + 队员名单，之后不再接受组队变动。

建议的角色（不是硬性）：

  • 架构师：拆任务、设计 Agent 流程、画架构图、写技术文档。
  • 工程师：写代码、跑 trace、修 bug。
  • 测试 / 用户研究员：找用户、做访谈、记反馈、画改进建议。
  • PM / 演示：写汇报、做 demo、回答答辩问题。

小组成员可以重叠角色，但每个人必须在最终复盘里写明「我具体干了什么」。

评分细则

维度占比评分要点
问题价值20%真实问题、真实用户、用户用了能省时间 / 多挣钱 / 学到东西。
技术深度25%合理使用工具 / RAG / 记忆 / 多智能体 / 评估；不是「调个 API 就完」。
可用性25%真有人用；用一周没崩；用户说「下次还愿意用」。
安全与伦理10%权限边界清晰、有审计、有降级方案、不传播有害内容。
复盘深度20%讲清楚踩了什么坑、改了什么、为什么改、下一步做什么。

选题灵感

下面这些是往届做过的项目，仅作参考，鼓励做新的。

学习类

论文综述、错题讲解、语言陪练、面试模拟、考研规划、笔记整理。

办公类

周报生成、会议纪要、邮件分类、合同比对、报销整理、PPT 大纲。

信息类

新闻摘要、舆情监测、行业周报、股票公告解读、招聘筛选、文献追踪。

生活类

差旅规划、装修清单、育儿助手、健身计划、宠物医疗记录、菜谱生成。

创作类

短视频脚本、公众号写作、小说情节辅助、播客选题、配图 prompt。

工具类

浏览器插件、VS Code 插件、命令行工具、微信机器人、飞书机器人。

选题三问：谁会用？省了多少时间 / 多少钱？4 周做得完吗？三问都答得上来再开始。

提交要求

  1. 源代码：GitHub 公开仓库，README.md 写清楚怎么跑。
  2. 演示视频：3–5 分钟，真实运行（不是录屏脚本）。
  3. 用户反馈：至少 3 份真实用户的反馈记录（截图 / 录音 / 文字均可）。
  4. 复盘文档：1000–2000 字，讲清楚踩坑、改进、下一步。
  5. 答辩：现场 10 分钟讲 + 5 分钟答 + 5 分钟互评。

提交方式：第 4 周周三晚 12 点前在课程 GitHub 组织里建 final-2025-XX-组名 仓库，按上述结构提交。
